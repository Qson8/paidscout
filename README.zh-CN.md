# PaidScout

[English](README.md) | **简体中文**

**给独立开发者的 App Store 付费离线应用调研引擎。**

PaidScout 每天盯着 App Store 付费榜，把它变成独立开发者能直接用的调研：哪些付费、离线、单机应用是真在动，哪些新入榜是真热，一个人或小团队还有哪些能做、且有人愿意付费的方向。

它复刻的是七麦 / Sensor Tower / data.ai 那套方法里**可复刻的那一层**——定时抓榜、排名落库、评分量增速跟踪、关键词名次——数据源只用**苹果官方免费接口：不用 Key、不用订阅、不用爬登录墙后面的数据**。

> **先说诚实口径：** PaidScout 绝不输出下载量、收入的「预估」数字。大平台的那些数字是靠用户面板校准的模型产物——榜单头部还有个方向，长尾就明显失真（我们实测抓到某大平台给一款日销约 260 份的付费应用显示收入 $0）。PaidScout 只报可验证的信号本身：名次、名次变化、评分量增量、价格、版本节奏、关键词名次。方法论全文见 [docs/METHODOLOGY.md](docs/METHODOLOGY.md)（英文）。

## 功能

- **双源榜单**——苹果旧版 RSS 榜与 MarketingTools 新版榜同时抓，美区＋中国区，付费榜＋畅销榜，总榜＋六个分类榜（游戏、工具、效率、教育、图形与设计、摄影与录像）。两套官方榜经常对不上（2026-11-07 实测美区前 50 只有约 36% 重合）；PaidScout 分开落库并标注分歧，**永不混排**。
- **历史与 diff**——全部数据落 SQLite。第二天起每份报告自动带：名次变化、新入榜、**评分量增量**（没有面板数据时最诚实的下载速度代理指标）、价格与版本变化。
- **观察名单跟踪**——给在意的应用（候选标的，也包括你自己的应用）跟踪关键词搜索名次与最新评论速度。
- **初筛过滤**——从商店文案里做离线/单机启发式判定，并标出大公司发行，让个人开发者能复制的应用从 Mojang、华纳、腾讯这类量级里显出来。启发式标签会明确标注为初筛，不冒充结论。
- **零依赖**——单个 Python 文件，只用标准库。

## 快速开始

```bash
git clone https://github.com/Qson8/paidscout.git
cd paidscout
python3 paidscout.py            # 完整一轮，约 2 分钟
python3 paidscout.py --quick    # 只跑总榜，更快
```

产出：`reports/report-YYYY-MM-DD.md` 日报一份，历史在 `data/monitor.db`。用 cron / launchd / GitHub Actions 每天跑，第二天起报告就开始带日环比变化。

## 配置

默认值都在代码里，要改就用 JSON 配置覆盖：

```bash
cp config.example.json config.json   # 改国家、关键词、观察名单
python3 paidscout.py --config config.json
```

观察名单是 `[应用ID, 国家, 备注名]` 的列表，同一个应用可以同时跟踪多个区。关键词按区分组，只有进入某个已跟踪关键词前 50 的应用才会出现在报告的关键词段里。

## 配 AI Agent 用（Skill 版）

仓库自带可安装的 Agent Skill：[`skill/SKILL.md`](skill/SKILL.md)。把它装给你的 Agent（Muse、Claude Code 或其他兼容 SKILL.md 的运行时），Agent 就能替你跑完整条工作流：每天执行引擎、复核初筛标签、按五轴给方向打分、维护候选池——同样守「不编造下载/收入数字」的口径。

## 调研工作流怎么用

PaidScout 是数据层。它服务的完整工作流是：

1. 每天跑一轮，先看新入榜和评分量增量异常的应用；
2. 给候选**方向**（不是克隆对象）按五轴打分：独立可复制性、离线纯度、出海适配、付费验证强度、与自己技术栈和既有资产的契合；
3. 维护候选池：掉出榜单或增速熄火的方向及时移出。

## 路线图

- 评论探针稳定性（个别区的评论 Feed 会间歇性返回 0）
- 单应用详情页（内购清单、版本间文案 diff）
- 可选的七麦 / Sensor Tower 人工抽查对照导入
- 排名历史曲线导出（CSV）
